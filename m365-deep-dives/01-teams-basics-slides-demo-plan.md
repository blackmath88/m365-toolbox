# 01 · Teams Basics — Structure, Slides and Demo Plan

Companion file to `01-teams-basics-facilitator-script.md`.

The purpose of this document is production coordination: what the audience sees, what the trainer demonstrates, and what must exist in the demo environment.

---

# Course architecture

```
PAIN
The file travels between people
      ↓
MENTAL MODEL
People come to the shared object
      ↓
MAP
Team → Channel → Post → File
      ↓
STORY
New person joins an existing team
      ↓
ORIENTATION
Find context, decision, file, owner
      ↓
COLLABORATION
Work on one shared object
      ↓
SELF-SERVICE
Activity → Search → Notifications
      ↓
TRANSFER
Same pattern in other work contexts
      ↓
COMPRESSION
Four rules
      ↓
ACTION
Try it in your own Teams
```

# Demo 1 — Orientation path

Trainer path:

```
Team
→ inspect channels
→ Organisation
→ Termin post
→ thread
→ linked/shared agenda
→ responsibility / @mention
```

## Demo discipline

Narrate **why** you click, not only what you click.

Good:

> „Ich kenne das Projekt noch nicht. Deshalb schaue ich zuerst nach der Struktur.“

Avoid:

> „Hier links sehen Sie jetzt die Kanalnavigation.“

# Slide language rules

Slides should:

- state one idea at a time;
- prefer diagrams over bullet lists;
- use the same visual metaphors repeatedly;
- use scenario cards immediately before demos;
- keep feature labels secondary to user questions.

Slides should not:

- reproduce the facilitator script;
- become screenshots of every click;
- contain dense feature matrices;
- explain architecture that is out of scope.

---

# Demo language rules

Every live demo should answer one of these questions:

1. **Wo bin ich?**
2. **Was ist passiert?**
3. **Wo ist der gemeinsame Arbeitsstand?**
4. **Wer ist zuständig?**
5. **Was braucht meine Aufmerksamkeit?**
6. **Wo war das nochmals?**

If a demo click does not help answer one of these questions, consider removing it.

---

# Production checklist

Before dry run:

- [ ] demo Team exists;
- [ ] fictional members exist or are convincingly represented;
- [ ] posts are seeded;
- [ ] threads contain realistic history;
- [ ] shared agenda is editable;
- [ ] Search reliably returns the intended example;
- [ ] Activity contains a prepared mention/reply;
- [ ] notification setting is known and stable;
- [ ] current Teams UI matches screenshots / trainer path;
- [ ] all demo accounts have correct access;
- [ ] backup screenshots exist for fragile live-demo moments.

During rehearsal:

- [ ] 45-minute stopwatch run;
- [ ] record actual time per block;
- [ ] note audience questions likely to derail;
- [ ] test house metaphor in German;
- [ ] test final two-minute action with a true beginner;
- [ ] cut variant block first if the session overruns.
